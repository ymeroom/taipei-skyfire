# Taipei SkyFire Testing & QA Report

**Date:** 2026-08-18 (Asia/Taipei)

**Baseline:** `a92e7d75710e5bb92e4903db97a40956e2f5f932`

**Surfaces:** `index.html`, `video.html`, `camera.html`, forecast/model modules, Ground Truth capture/scoring workflows

## Executive result

The original Ground Truth Verification Corridor was not valid ground truth. Its capture pipeline downloaded YouTube thumbnails and reused static repository images; its scoring pipeline could generate an observation from the prediction plus random noise. Existing accuracy and MAE values therefore cannot be treated as scientific validation.

The local working tree now rejects those records and implements a provenance-gated livestream capture path. It has not been deployed. The first end-to-end real capture must occur during the next actual sunrise or sunset window on the GitHub Actions Linux runner.

## Root causes confirmed

| Severity | Finding | Evidence | Local disposition |
|---|---|---|---|
| Critical | `maxresdefault.jpg`/`hqdefault.jpg` are static YouTube thumbnails, not live frames. | `capture-validation.js` downloaded from `i.ytimg.com`; `2026-08-18-sunrise.jpg` is visibly a channel cover. | Removed thumbnail path; capture now requires validated live HLS metadata and ffmpeg. |
| Critical | Static/generated fallback images were accepted as observations. | Legacy records reference `assets/epic_sunset.jpg`; fallback copied `*-live.jpg`. | No fallback image is allowed; legacy records remain on disk but are excluded from UI and metrics. |
| Critical | Failed optical analysis could create a score near the model prediction. | Old scorer used `predScore + random noise` and then marked the record completed. | Simulated scoring removed; analyzer failure exits non-zero without modifying records. |
| High | Both scheduled cron events defaulted to `sunset`. | `${{ github.event.inputs.session || 'sunset' }}` is `sunset` for scheduled events. | Workflow now maps each schedule explicitly and passes one resolved session to both phases. |
| High | Capture time was never checked against the astronomical event. | A manual run at 08:03 local was labeled sunrise even though sunrise was about 05:30. | Capture is rejected outside ±30 minutes of the calculated event. |
| High | Sunrise UTC date could be recorded as the previous Taipei date. | Date used `toISOString().split('T')[0]`. | Date is now derived in `Asia/Taipei`; Actions job sets `TZ=Asia/Taipei`. |
| High | Scorer could score `records[0]` when the requested record was absent. | Old lookup used `find(...) || records[0]`. | Exact `date + session` record is mandatory. |
| Medium | An image could be changed after capture but before scoring. | No integrity binding existed. | SHA-256 is recorded at capture and verified before optical scoring. |

## Remaining validation gate

The local Windows environment does not have `yt-dlp`, `ffmpeg`, or Python installed, and the current time was outside the sunrise/sunset window. Therefore no replacement image was fabricated. Final acceptance requires one scheduled GitHub Actions run during an actual event window and confirmation that the resulting record contains:

- `capture.kind = "youtube-live-frame"`
- `capture.validated = true`
- official `videoId` and `uploaderId`
- event time and offset within ±30 minutes
- frame width/height and SHA-256
- `verification.isSimulated = false`

## Other QA observation

The homepage button `日落首選 (8)` renders 10 cards because the filter also includes two `both` locations. Likewise, the sunrise filter includes dual-purpose locations. This is a minor label/expectation mismatch and was not changed in the Ground Truth fix.
